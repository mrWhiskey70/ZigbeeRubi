Target управление разрешено для стандартных OnOff endpoints, подтверждённых отчётами. Неизвестные Tuya DP не используются новыми сценариями. FreeRTOS очередь и NVS adapter скомпилированы, аппаратное исполнение ещё не проверено. Следующий этап — [hardware-first-run.md](hardware-first-run.md), сбор точных fingerprints и проверка заказанных устройств.

На телефоне — плавающая панель вкладок, на компьютере — боковое меню. Шрифт системный (SF Pro на iPhone), иконки — встроенные SVG. Набор файлов `components/web_ui/assets/` не менялся, сборка и обработчики статики не затронуты. Функции прототипа, которых нет в движке, в интерфейс не добавлялись.

После UX-ревью интерфейса: сводка состояния дома вместо метрик хаба; плитки датчиков открывают карточку устройства (переименование и удаление в листе, без prompt/confirm); панель симулятора перенесена в «Настройки»; в списке сценариев — описание фразой, нажатие открывает редактор; в редакторе — шаблоны, пометка «запускает / проверяется» у условий, переключатели вместо списков для двух состояний, действие «Включить на время», подтверждение при закрытии с несохранёнными изменениями, удаление сценария с отменой; экран «Нет связи с хабом»; интерфейс перерисовывается только при изменении данных. ## Что требует оборудования

| Параметр | Статус |
|---|---|
| Точная ревизия платы / физические 16 МБ Flash | Со слов пользователя; проверить на плате |
| Дверь: modelID / manufacturerName / endpoints | Неизвестны |
| PIR: modelID / manufacturerName / reporting | Неизвестны |
| Выключатель: три независимых канала / ZCL или Tuya DP | Не проверены |
| Одновременная работа Wi-Fi и Zigbee | Не проверена |
| Сохранение сети и сценариев после перезагрузки | Не проверено на плате |

`hardware_verified = false`. Успешные host-тесты не заменяют аппаратную проверку.

## Ведение проекта

Код и актуальные документы хранятся здесь. При изменении требований обновляется технический проект, при изменении порядка работ — план; при завершении этапа — этот статус с конкретными результатами проверки. Нельзя обозначать этап реализованным только по описанию в документации.
