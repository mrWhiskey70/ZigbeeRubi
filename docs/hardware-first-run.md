# Первый запуск на оборудовании

Статус: hardware_verified=false. Проверки ниже ещё не выполнялись; заполнять фактические результаты, а не ожидания.

1. Проверить маркировку ESP32-C6, USB-порт и Flash через esptool `flash_id`. Сохранить ревизию платы, идентификатор Flash и объём. Профиль рассчитан на16МБ, нативный координатор802.15.4; ESP32-S3 не заменяет C6.
2. Прошить по [README_RU](../README_RU.md). Проверить загрузку, отсутствие panic/brownout; память измерить `heap_caps_get_free_size`, минимум heap и `uxTaskGetStackHighWaterMark` сервисной задачи при заполнении24правил/16устройств. Размер статического RAM в отчёте сборки не доказывает достаточный heap.
3. Выполнить AP → STA настройку. Проверить, что Zigbee запускается после настройки, AP выключен. Проверить http://zigbeerubi.local и IP из роутера, отсутствие баннера симулятора; `/api/v1/sim/report` и `/sim/advance` должны отдавать404.
4. Открыть окно подключения60с. Сбросить/спарить сначала дверь, затем PIR. Зафиксировать EUI64, manufacturerName, modelID, endpoints, input/output clusters, ZCL type, исходные сообщения и реальные переходы. Старый диагностический `/api/devices` содержит manufacturer/model. Не публиковать ключ сети Zigbee или данные Wi-Fi.
5. Для контакта проверить стандартный IAS0500, для PIR — Occupancy0406; IAS PIR требует проверки zone type и отдельного корректного адаптера. Первый отчёт после загрузки должен только заполнить UNKNOWN, второй переход — запустить событие. Проверить повтор одного состояния, wake-up батарейного датчика и потерю связи.
6. Проверить выключатель с подходящей лампой/нагрузкой и байпасом согласно его инструкции. При работах с230В используйте квалифицированного специалиста. Проверять по одному каналу: endpoint команды, отчёт endpoint, какая кнопка/лампа изменилась, остальные два канала. Перепроверить соответствие логических каналов после reboot/rejoin.
7. Если устройство использует EF00: собрать точный fingerprint и сырые DP-пакеты для каждого из трёх каналов. После этого добавить отдельную проверенную карту и её тесты; не считать DP1/2/3 известными заранее. До этого новые сценарии не управляют Tuya DP.
8. Проверить «движение → ON → 60с → OFF» с закрытым браузером. При ручном управлении этим каналом ожидающий OFF отменяется. Устройство без отчёта состояния: timeout, без повторной команды и без следующего действия.
9. Сохранить сценарии/имена/UTC+7, перезагрузить. Должны сохраниться сеть и правила; состоянияUNKNOWN, журнал пуст, старые таймеры не исполняются. Rejoin с новым short_addr сохраняет EUI64 и правила. Новый владелец того же short_addr не получает старые настройки/сценарии.
10. Проверить Wi-Fi/Zigbee coexistence при частом HTTP-опросе и потоке датчиков; переподключение Wi-Fi, работа при недоступном SNTP, power-cycle, OTA и сохранение сети. Обрыв питания при записи NVS проверять на стенде с резервной копией; сохранённая предыдущая конфигурация должна восстановиться.
