# Запуск ZigbeeRubi

Исходники, правила проекта и результаты проверок: https://github.com/mrWhiskey70/ZigbeeRubi.

## Симулятор до доставки платы

Нужны Python3, CMake, GCC/Clang с C++17. Windows: удобнее WSL2.

```sh
git clone https://github.com/mrWhiskey70/ZigbeeRubi.git
cd ZigbeeRubi
git switch feat/scenarios-mvp
bash scripts/run_simulator.sh
```

Откройте **http://127.0.0.1:8080**. Жёлтая надпись «Симулятор» означает виртуальные датчики и выключатель. На компьютере работает C++ процесс с тем же движком и API, что встроены в прошивку. Браузер показывает интерфейс; закрытие страницы не останавливает таймеры.

1. Откройте «Сценарии» → «Создать сценарий». Пример уже заполнен: движение → канал1 ON → задержка60с → OFF.
2. Сохраните. В панели симулятора нажмите «Обнаружить»; состояние канала изменится.
3. Кнопками +59с и +1с проверьте задержку. В «Журнале» видны результат условия, команды и подтверждения.
4. Добавьте группы И/ИЛИ, условия датчиков и окна времени. Доступны отдельные каналы и последовательные действия.
5. «Перезапуск» сохраняет сценарии и имена, очищает известные состояния, журнал и ожидающие действия. Первый новый отчёт восстанавливает состояние без запуска правила.

Настройки сохраняются в `.sim-data`. Для отдельного стенда: `bash scripts/run_simulator.sh --data-dir /tmp/rubi-demo --port 8081`. Детерминированный режим для тестов: `--virtual-time`; время меняется только через панель/API. Без этого флага есть реальный тик каждые100мс.

Готовые сборки после успешного CI доступны в GitHub Actions: [скачивание и прошивка](docs/firmware-artifact.md).

## Сборка прошивки C6 / 16МБ

Установите **ESP-IDF v5.5.2**, инструменты `esp32c6` и активируйте `export.sh`. Flash16МБ указана в профиле, **PSRAM не требуется**. Версии библиотек фиксирует `dependencies.lock`.

```sh
bash scripts/build_prototype.sh
idf.py -B build-c6 -p /dev/ttyACM0 flash monitor
```

Перед прошивкой проверьте реальный объём Flash через `python -m esptool --chip esp32c6 --port PORT flash_id`. Если Flash меньше16МБ, текущую таблицу разделов использовать нельзя. Порт в Windows — например `COM5`. Первичная прошивка пишет новую таблицу: старые данные с другой разметкой требуют отдельного резервного копирования/очистки.

При первом запуске подключитесь к временной открытой сети **zigbeerubi**, откройте **http://192.168.4.1**, перейдите в «Настройки» и задайте домашний Wi-Fi. После перехода в домашнюю сеть откройте **http://zigbeerubi.local** либо IP из роутера. Zigbee стартует после подключения STA. После старта сеть Zigbee и сценарии продолжают работать при потере Wi-Fi; фронт снова доступен после восстановления связи.

Начальный часовой пояс — UTC+7 (Томск). SNTP синхронизирует часы через `pool.ntp.org`; до синхронизации окно времени имеет UNKNOWN. Отсутствие интернета не мешает обычным событиям и монотонным задержкам.

## Граница готовности

Прошивка собирается, но **не проверена на плате**. Для новых сценариев разрешены только стандартные OnOff endpoints, подтверждённые отчётами устройства. Логические номера каналов назначаются при обнаружении endpoint и сохраняются. Первичную привязку «канал → кнопка выключателя» проверяем физически.

Tuya DP-карта заказанного трёхканального выключателя неизвестна. До захвата точного `manufacturerName/modelID`, endpoints и payloads управление через DP не разрешено. Однотипное название TS0601 не доказывает совместимость. Успешный APS/ZCL ACK ещё не подтверждает включение: требуется отчёт состояния, иначе через5с timeout без повторной команды.
